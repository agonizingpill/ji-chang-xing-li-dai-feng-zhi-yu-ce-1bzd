# Airside Flow · 机场行李带峰值预测

`gb-1072` 是面向机场运行控制团队的行李波次预测与岗位排班应用。模拟客户是星港机场 T2 运行控制中心，团队每天把航班到达波次、转盘计数器和人工排班表合并成一张运行表，再交给值班经理决定是否加派机动人员。

## 业务范围

- 航班波次。按航站楼和到达时间窗合并航班，记录计划行李量和取消/改降标记。
- 行李带计数。每一条计数绑定波次、行李带、时间点和采集来源，重复时间点受唯一约束。
- 峰值预测。worker 消费 Redis 队列，执行 STL 风格季节分解与滚动窗口线性回归，结果和输入摘要写回 PostgreSQL。
- 人员班次。记录班次、岗位容量和确认人。计划人数超过容量时进入待值班经理确认状态。
- 拥堵复盘。记录现场峰值、排队分钟、原因与处置动作，主管关闭复盘单后完成闭环。

主流程是航班波次导入 → 行李带计数 → 时序分解 → 峰值预测 → 人员班次确认 → 拥堵复盘。取消或改降未完成标记时，预测请求返回 409。预测峰值超过岗位容量时，发布请求会先把班次置为 `needs_confirmation`，只有 `supervisor` 留下确认说明后才能发布。

## 算法口径

输入是按时间排序的同一波次行李带计数。系统内置两版峰值算法，由 `algorithm_settings` 单行表记录当前生效版本（初始为旧版）：

- **旧版 `stl_rolling`**：STL 风格分解按 4 或 8 个采样点构造季节模板，使用移动平均获得趋势，最近 `window_size` 个去季节化点通过一元线性回归外推未来 4 个点，至少需要 8 个计数点。
- **候选版 `recent_four_mean`**：取最近四笔已接受计数的算术均值作为预测峰值（不足 4 点拒绝计算），未来 4 点以同一均值水平给出。

两版输出结构一致（峰值、未来 4 点、季节强度、趋势、窗口、周期、输入快照 SHA-256、输入点数），同一批计数在两版下得到相同的 `snapshot_hash`，用于核对试算口径一致。固定演示种子记录为 `1072`，演示训练数据是 seed 生成的合成计数。

### 换版试算与一次性切换

值班经理可在「预测排班」页指定波次发起两版试算（`POST /algorithm/trials`，仅 supervisor）：

1. 系统为该波次用**同一批已接受计数**各建一条 `purpose='trial'` 的试算预测，分别走旧版与候选版，经同一 Redis 队列由 worker 计算；试算预测不改变波次状态、不出现在正式预测队列，也不能发布，试算期间排班照旧。
2. 两版试算都成功（`ready`）且快照哈希一致时，该波次才标记为可切换；任一版失败、仍在计算或输入批次不一致，切换保持锁定并保留旧版，可重新发起试算（复用原任务重新排队）。
3. 所有指定波次均通过后，经理通过 `POST /algorithm/switch` **一次性**把生效版本切换为候选版；切换后新建预测（`POST /forecasts`）自动使用生效版本及其最少计数点要求（候选版 4 点、旧版 8 点）。
4. 发布门禁（`POST /forecasts/{id}/publish`）只允许发布当时生效版本的正式预测：非生效版本的就绪预测与试算预测一律 409；已发布预测永久保留其生成时的算法版本与原峰值，重复发布幂等返回，已发排班仍可查原峰值。

`GET /algorithm/overview` 返回生效版本、候选版信息与每个试算波次的两版状态/峰值/阻断原因，供排班页面展示。

## 技术结构

- `backend/src/app.py` 提供认证、领域路由、状态前置条件和审计记录。
- `backend/src/algorithm.py` 提供可复现的 STL 风格分解、最近四笔均值候选算法与版本分派。
- `backend/src/worker.py` 负责 Redis 队列消费、按算法版本分派、试算任务隔离、失败写回和心跳文件。
- `backend/src/db.py` 创建 PostgreSQL 领域表和审计表。
- `backend/scripts/seed_demo.py` 使用业务编号和唯一约束实现幂等 seed。
- `frontend/src/app.js` 和 `frontend/src/styles.css` 提供原生 HTML/CSS/JS 控制台。

共享枚举在后端 `db.py` 的 CHECK 约束、前端 `badge()` 的状态字典和 `app.js` 的角色文案中分别定义。JWT 认证、审计日志、请求 ID 和错误响应是横切能力。


## 业务核验模块

登录后打开页面右下角的「业务核验」。可从实时业务台账筛选记录、导出所选结果，主管可对当前证据签认并填写说明。

- **行李带计数覆盖审计** 核对波次是否有有效采样、计数是否落在到达窗口内。窗口外采样须由值班人员复核。
- **排班重叠核对** 同航站楼的有效班次若时段重叠，交值班经理确认岗位能否并行覆盖。相邻但互不重叠的班次不计为冲突。
- **峰值预测兑现追踪** 对照预测峰值与拥堵复盘实测，高出预测的高峰交给下轮模型校准。
- **峰值时点保障缺口** 只统计覆盖预测峰值时点的已确认班次容量；系统显示预计尚缺的保障量。

### 二次扩展核验

- **取消与备降波次核销** 对照航班波次标记与最近预测状态，优先处理取消未标和停用波次中的遗留发布。
- **首件行李接驳偏差** 逐波次和行李带定位首个实际有件的有效计数，对照波次窗口识别等待或时间对齐异常。
- **拥堵复盘行动回收** 按复盘行动、当时排队分钟和处置状态分拣主管待关闭事项。

## 业务处置与验收

登录后打开「航班波次保障与交接」。操作员提交结果、凭证号和说明，主管可复核关闭或退回补证，观察员可查看记录。关闭时复查源业务状态，处置历史保留每次操作。

- 取消备降波次发布核销
- 首件接驳放行
- 峰值班组保障验收
- 拥堵复盘对外交接
- 波次发布与保障看板
